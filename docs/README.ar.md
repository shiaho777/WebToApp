# WebToApp

**حوّل أي موقع ويب إلى تطبيق قابل للتثبيت — في ثوانٍ.**

## ما الذي تحصل عليه

أدخل رابطاً — أو ارفع ملف `.html` / `.zip` الخاص بك — وبعد ثوانٍ تحصل على نتيجة قابلة للتثبيت تغطي كل المنصات. كل حزمة هي غلاف أصلي رقيق يشير إلى موقعك، لذا تُقاس أحجامها **بالكيلوبايت لا بالميجابايت** وتُحمَّل شبه فورياً.

كل تطبيق مُنشأ يعيش في صفحة تحميل خاصة به `/a/<id>`: خيارات تثبيت لكل منصة، وقسم قابل للطي بعنوان «عن هذه الصفحة» يمكن للمنشئ ملؤه بمحتوى حقيقي، وطبقة مجتمعية فيها تعليقات وتقييمات بالنجوم. انشره كرابط عام فيظهر أيضاً في **سوق التطبيقات** ليكتشفه الجميع.

مفتوح المصدر · مجاني · بلا تسجيل. جرّبه مباشرة على **[shiaho.sbs](https://shiaho.sbs)**.

## كيف يعمل

<p align="center"><img src="assets/fig-pipeline.svg" alt="خط المعالجة: إدخال رابط أو HTML → تحليل + recipe → خمس عمليات بناء متوازية → صفحة تطبيق مع مجتمع" width="800"></p>

1. **الإدخال** — الصق رابط موقع، أو ارفع ملف `.html` مفرداً / ملف `.zip` يحوي `index.html`. يُستضاف HTML المرفوع على الخادم تحت `/a/<id>/site/...` ويُغلَّف تماماً كتطبيق رابط.
2. **التحليل + recipe** — يجلب المُحلِّل الصفحة ويستخرج الاسم ولون السمة والأيقونة (متعدد المرشحين، تفوز أفضل دقة)؛ كل ما تحتاجه عملية البناء يُثبَّت في `recipe.json`.
3. **بنات متوازية** — تُبنى الحزم الخمس معاً؛ فشل إحداها (مثلاً غياب أدوات Android) يُخفِّض تلك المنصة وحدها.
4. **صفحة التطبيق** — تعرض صفحة التحميل مدخلات التثبيت لكل منصة ومحتوى «عن هذه الصفحة» من المنشئ وكتلة المجتمع.

## الميزات

- **وضعا إدخال**: رابط موقع، أو HTML خاص بك (ملف `.html` أو `.zip` يحوي `index.html`) — يُستضاف ويُغلَّف كأي تطبيق رابط.
- **تحليل الموقع**: الاسم ولون السمة وأيقونة بأفضل دقة وعدّ الإعلانات/المتعقّبات/النوافذ المنبثقة (تقديرات للعرض فقط).
- **تغليف متعدد المنصات**، بناء واحد → خمس حزم:
  - **Android** — WebView APK حقيقي قابل للتثبيت (موقَّع v1+v2+v3)، ولكل تطبيق **شهادة توقيع خاصة به**.
  - **iOS / iPadOS** — ملف تعريف Web Clip بصيغة `.mobileconfig`، مع توقيع CMS اختياري بشهادة CA عامة (تثبيت «بلا توقيع»).
  - **macOS** — نافذة `.app` مستقلة على WKWebView (بلا شريط عنوان، بلا متصفح طرف ثالث).
  - **Windows / Linux** — مشغّلات خفيفة `.bat` / `.desktop` تفتح متصفح النظام في وضع التطبيق.
- **قسم «عن هذه الصفحة» بقلم المنشئ**: نص منسّق بالإضافة إلى حتى 3 صور في كل صفحة تطبيق. تُتحقَّق الملفات المرفوعة بفك الترميز، وتُجرَّد من EXIF، وتُعاد ترميزتها إلى WebP — وما يتجاوز 800KB يُضغط على الخادم شبه بلا فقدان.
- **مجتمع بلا حسابات**: بصمة الجهاز تصبح هوية عامة دائمة (`?u=N`) — اسم قابل للتعديل ونبذة Markdown وصورة رمزية. يُنسب المنشئون على تطبيقاتهم ولديهم صفحة ملف عامة.
- **تعليقات وتقييمات**: لكل صفحة تطبيق سلسلة تعليقات مع تقييم اختياري من 1–5 نجوم؛ تظهر المتوسطات على بطاقات السوق.
- **سوق تطبيقات عام**: فلاتر وسوم وبحث وترتيب بالأحدث أو الأعلى تقييماً (المتوسط ← العدد) أو الأكثر تحميلاً أو الأكثر زيارة — بطوابع زمنية نسبية.
- **تبديل ديناميكي للرابط على iOS**: يشير Web Clip إلى `/a/<id>/launch`، فيمكن تغيير الرابط الهدف من الخادم دون إعادة تثبيت.
- **سجل لكل جهاز**: تُحفَظ البنات مقابل بصمة الجهاز مع إحصاءات الزيارات/التحميلات وإعادة التوليد والتصدير/الاستيراد بين الأجهزة. حذف سجل يزيل التطبيق بالكامل.
- **تنظيف تلقائي**: التطبيقات بلا زيارات لمدة 30 يوماً تُستصلَح تلقائياً.
- **تفريغ اختياري إلى Cloudflare R2**: تُعاد توجيه التحميلات إلى CDN موفِّرةً عرض نطاق المصدر.
- **واجهة متعددة اللغات**: 9 لغات — English، 简体中文، 日本語، العربية (RTL)، Русский، Español، Português، Français، Deutsch — وصفحات التحميل المُنشأة مترجمة هي الأخرى.

## مجتمع بلا تسجيل

<p align="center"><img src="assets/fig-community.svg" alt="بصمة الجهاز تصبح معرّفاً عاماً متسلسلاً يفتح إسناد المنشئ والملفات والتعليقات والتقييمات" width="800"></p>

لا يوجد تسجيل: عند أول ظهور لجهاز ما، تحصل بصمته على رقم عام متسلسل. يصبح هذا `#N` ملفاً شخصياً حقيقياً — عيّن اسماً معروضاً ونبذة Markdown وصورة رمزية، وكل تطبيق تنشره يحمل بطاقة المنشئ الخاصة بك. يفتح الآخرون `?u=N` لرؤية ملفك العام والتطبيقات التي نشرتها. تقبل التعليقات تقييمات نجوم اختيارية تنعكس على كل بطاقة في السوق.

## حجم التطبيق

كل حزمة هي بوابة رقيقة إلى موقعك — لا تتضمن محتوى الموقع، لذا تُقاس الحزم **بالكيلوبايت لا بالميجابايت**.

<p align="center"><img src="assets/fig-sizes.svg" alt="أحجام الحزم المقاسة: macOS ‏135KB، Android ‏21KB، iOS ‏4KB، Windows ‏1.2KB، Linux ‏0.7KB" width="760"></p>

| المنصة | الحزمة | الحجم النموذجي | المحتوى |
| --- | --- | --- | --- |
| Android | `android.apk` | **~21 KB** | WebView APK حقيقي قابل للتثبيت (موقَّع v1+v2+v3) |
| iOS / iPadOS | `ios.mobileconfig` | **~4 KB** | ملف تعريف Web Clip |
| macOS | `macos.zip` | **~135 KB** | حزمة `.app` (نافذة WKWebView أصلية + أيقونة) |
| Windows | `windows.zip` | **~1.2 KB** | مشغّل `.bat` + مساعد اختصار + أيقونة |
| Linux | `linux.tar.gz` | **~0.7 KB** | إدخال `.desktop` + سكربت تثبيت + أيقونة |

## الحزمة التقنية

- الخلفية: Python + FastAPI + Uvicorn · مخازن SQLite (السجل، المهام، المجتمع)
- الواجهة: HTML / CSS / JS خام — بلا خطوة بناء، يقدّمها الخادم مباشرة
- التغليف: Android SDK (aapt2 / d8 / apktool / apksigner / zipalign)، Pillow، openssl
- CI: `pytest tests/` على Python 3.10 / 3.11 / 3.12 — **336 اختباراً**

## البدء السريع

يتطلب Python 3.10+. بناء APK لأندرويد يحتاج Android SDK و`apktool` (يتراجع إلى حزمة PWA دون اتصال عند غيابهما).

```bash
# 1. أنشئ بيئة افتراضية وثبّت الاعتماديات
python3 -m venv venv
source venv/bin/activate
pip install -r server/requirements.txt

# 2. الإعداد (اختياري، لكل شيء قيم افتراضية)
cp .env.example .env
# عدّل .env حسب الحاجة

# 3. التشغيل
uvicorn server.main:app --host 127.0.0.1 --port 8000
```

افتح http://127.0.0.1:8000.

> لا حاجة لمتغيرات بيئة للتطوير المحلي. عند النشر العام عيّن `PUBLIC_BASE_URL`،
> وإلا لن تستطيع أجهزة iPhone فتح `localhost`. القائمة الكاملة في [`.env.example`](../.env.example).

## النشر

> لدليل إنتاج كامل خطوة بخطوة (systemd، Nginx، HTTPS، Android/iOS، R2) راجع **[DEPLOY.md](DEPLOY.md)**.

في الإنتاج يُشغَّل عادةً تحت systemd خلف بروكسي عكسي Nginx:

```ini
# /etc/systemd/system/webtoapp.service
[Unit]
Description=WebToApp
After=network.target

[Service]
WorkingDirectory=/path/to/web-to-app
Environment=PUBLIC_BASE_URL=https://your-domain.com
ExecStart=/path/to/web-to-app/venv/bin/uvicorn server.main:app --host 127.0.0.1 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
```

لتوقيع ملفات iOS (تثبيت «بلا توقيع») راجع إعداد الشهادات في [`certs/README.md`](../certs/README.md).

## كيف يعمل التفريغ إلى Cloudflare R2

المثبّتات المولّدة قد تكون كبيرة، وتقديم كل تحميل من المصدر يستهلك عرض نطاقه. مع ضبط R2:

1. **بعد كل بناء**، يُعكَس كل ملف في `generated/<app_id>/downloads/` إلى R2 تحت المفتاح `<app_id>/downloads/<filename>` (`server/engine/storage.py`)، وتُكتب الروابط العامة الناتجة في `recipe.json` للتطبيق كخريطة `downloads_cdn`.
2. **عند التحميل**، يفضّل `GET /a/<id>/download/<platform>` رابط CDN في `downloads_cdn` ويعيد **إعادة توجيه 302** إلى R2؛ وعند غيابه يتراجع إلى تدفق الملف المحلي. يستهلك المصدر المعالج في البناء، لا عرض النطاق في كل مشاركة أو مسح QR.
3. **عند التنظيف**، تُحذَف كائنات التطبيق تحت `<app_id>/` من R2 مع بياناته المحلية.

إن غاب أي متغير `R2_*` تصبح الميزة عديمة الأثر وتُقدَّم التحميلات محلياً — لا شيء ينكسر. يمكن ترحيل التطبيقات المُنشأة قبل تفعيل R2 عبر `python -m server.scripts.backfill_r2`. الخطوات الكاملة (الحاوية، رمز API، الوصول العام، النطاق المخصص، الملء الرجعي) في [DEPLOY.md §11](DEPLOY.md#11-cloudflare-r2-offload-optional).

## ملاحظات أمنية

- تُقرأ كل الأسرار (R2، Cloudflare، كلمات مرور التوقيع) من متغيرات البيئة؛ لا يحوي المستودع أي بيانات اعتماد حقيقية.
- **مفاتيح التوقيع الخاصة (`certs/*.keystore`، `certs/app-keys/`) وبيانات التشغيل (`generated/`) مستبعدة افتراضياً عبر `.gitignore` — لا ترفعها أبداً.**
- يستخدم كل تطبيق Android مولَّد شهادة توقيع مستقلة خاصة به، ما يمنع تمييز بصمة الشهادة جماعياً ويضمن إمكانية تحديث التطبيق نفسه في مكانه.
- صور «عن هذه الصفحة» التي يرفعها المنشئون تُتحقَّق بفك الترميز عبر Pillow، وتُقيَّد بأسقف الحجم الخام / البكسلات / العدد، وتُجرَّد من البيانات الوصفية وتُعاد ترميزتها إلى WebP — لا تُقدَّم أبداً كما رُفعت.
- النص الذي ينتجه المستخدمون يُهرَّب HTML عند العرض؛ ومسارات وسائط التطبيقات لا تسمح إلا بأسماء ملفات يولّدها الخادم.
