# WebToApp

**Превратите любой сайт в устанавливаемое приложение — за секунды.**

## Что вы получаете

Введите URL — или загрузите свой `.html` / `.zip` — и через несколько секунд получите устанавливаемый результат для всех платформ. Каждый артефакт — тонкая нативная оболочка, указывающая на ваш сайт, поэтому размер пакетов измеряется **килобайтами, а не мегабайтами**, и они скачиваются почти мгновенно.

Каждое созданное приложение живёт на собственной странице загрузки `/a/<id>`: варианты установки по платформам, сворачиваемая секция «Об этой странице», которую автор может заполнить реальным содержимым, и слой сообщества с комментариями и звёздными оценками. Опубликуйте публичную ссылку — и приложение также появится в **маркете приложений** для всех.

Open source · Бесплатно · Без регистрации. Попробуйте вживую: **[shiaho.sbs](https://shiaho.sbs)**.

## Как это работает

<p align="center"><img src="assets/fig-pipeline.svg" alt="Конвейер: ввод URL или HTML → анализ + recipe → пять параллельных сборок → страница приложения с сообществом" width="800"></p>

1. **Ввод** — вставьте URL сайта или загрузите одиночный `.html` / `.zip` с `index.html` внутри. Загруженный HTML хостится на сервере под `/a/<id>/site/...` и упаковывается точно так же, как приложение по URL.
2. **Анализ + recipe** — анализатор загружает страницу и извлекает имя, цвет темы и иконку (мультикандидатный поиск, побеждает лучшее разрешение); всё необходимое для сборки фиксируется в `recipe.json`.
3. **Параллельные сборки** — пять пакетов строятся одновременно; сбой одного (например, отсутствие тулчейна Android) деградирует только эту платформу.
4. **Страница приложения** — страница загрузки рендерит записи установки по платформам, авторское содержимое «Об этой странице» и блок сообщества.

## Возможности

- **Два режима ввода**: URL сайта или собственный HTML (одиночный `.html` или `.zip` с `index.html`) — хостится и упаковывается как любое приложение по URL.
- **Анализ сайта**: имя, цвет темы, иконка в лучшем разрешении и подсчёт рекламы/трекеров/попапов (оценки только для показа).
- **Мультиплатформенная упаковка**, одна сборка → пять артефактов:
  - **Android** — настоящий устанавливаемый WebView APK (подписан v1+v2+v3), у каждого приложения **свой собственный сертификат подписи**.
  - **iOS / iPadOS** — профиль Web Clip `.mobileconfig`, опционально CMS-подпись публичным CA-сертификатом (установка «без подписи»).
  - **macOS** — автономное окно `.app` на WKWebView (без адресной строки, без стороннего браузера).
  - **Windows / Linux** — лёгкие лаунчеры `.bat` / `.desktop`, открывающие системный браузер в режиме приложения.
- **Секция «Об этой странице» от автора**: rich text плюс до 3 изображений на каждой странице приложения. Загрузки проверяются декодированием, очищаются от EXIF и перекодируются в WebP — всё, что больше 800 КБ, сжимается на сервере практически без потерь.
- **Сообщество без аккаунтов**: отпечаток устройства становится постоянной публичной идентичностью (`?u=N`) — редактируемое имя, Markdown-био и аватар. Авторы указываются на своих приложениях и имеют публичную страницу профиля.
- **Комментарии и оценки**: на каждой странице приложения есть лента комментариев с опциональной оценкой 1–5 звёзд; средние значения видны на карточках маркета.
- **Публичный маркет приложений**: фильтры по тегам, поиск и сортировка по новизне, рейтингу (среднее → количество), загрузкам или посещениям — с относительным временем.
- **Динамическая смена URL на iOS**: Web Clip указывает на `/a/<id>/launch`, так что целевой URL можно менять на сервере без переустановки.
- **История по устройству**: сборки сохраняются к отпечатку устройства со статистикой посещений/загрузок, пересборкой и экспортом/импортом между устройствами. Удаление записи полностью стирает приложение.
- **Автоматическая очистка**: приложения без посещений 30 дней собираются автоматически.
- **Опциональный оффлоад на Cloudflare R2**: загрузки перенаправляются на CDN, экономя трафик origin.
- **Многоязычный UI**: 9 языков — English, 简体中文, 日本語, العربية (RTL), Русский, Español, Português, Français, Deutsch — сгенерированные страницы загрузки тоже локализованы.

## Сообщество без регистрации

<p align="center"><img src="assets/fig-community.svg" alt="Отпечаток устройства становится последовательным публичным ID, открывающим атрибуцию автора, профили, комментарии и оценки" width="800"></p>

Регистрации нет: при первом появлении устройства его отпечаток получает последовательный публичный номер. Этот `#N` становится настоящим профилем — задайте отображаемое имя, Markdown-био и аватар, и каждое опубликованное приложение будет нести вашу карточку автора. Другие открывают `?u=N`, чтобы увидеть ваш публичный профиль и опубликованные приложения. Комментарии принимают опциональные звёздные оценки, отражающиеся на каждой карточке маркета.

## Размер приложения

Каждый пакет — тонкая точка входа на ваш сайт: он не включает содержимое сайта, поэтому артефакты измеряются **килобайтами, а не мегабайтами**.

<p align="center"><img src="assets/fig-sizes.svg" alt="Измеренные размеры пакетов: macOS 135 КБ, Android 21 КБ, iOS 4 КБ, Windows 1,2 КБ, Linux 0,7 КБ" width="760"></p>

| Платформа | Пакет | Типичный размер | Содержимое |
| --- | --- | --- | --- |
| Android | `android.apk` | **~21 КБ** | Настоящий устанавливаемый WebView APK (подписан v1+v2+v3) |
| iOS / iPadOS | `ios.mobileconfig` | **~4 КБ** | Профиль конфигурации Web Clip |
| macOS | `macos.zip` | **~135 КБ** | Бандл `.app` (нативное окно WKWebView + иконка) |
| Windows | `windows.zip` | **~1,2 КБ** | Лаунчер `.bat` + помощник ярлыка + иконка |
| Linux | `linux.tar.gz` | **~0,7 КБ** | Запись `.desktop` + скрипт установки + иконка |

## Технологический стек

- Бэкенд: Python + FastAPI + Uvicorn · SQLite-хранилища (история, задачи, сообщество)
- Фронтенд: чистые HTML / CSS / JS — без шага сборки, отдаётся напрямую бэкендом
- Упаковка: Android SDK (aapt2 / d8 / apktool / apksigner / zipalign), Pillow, openssl
- CI: `pytest tests/` на Python 3.10 / 3.11 / 3.12 — **336 тестов**

## Быстрый старт

Требуется Python 3.10+. Для сборки Android APK нужны Android SDK и `apktool` (при их отсутствии — откат на офлайн-PWA-пакет).

```bash
# 1. Создайте виртуальное окружение и установите зависимости
python3 -m venv venv
source venv/bin/activate
pip install -r server/requirements.txt

# 2. Настройте (опционально, у всего есть значения по умолчанию)
cp .env.example .env
# Отредактируйте .env при необходимости

# 3. Запустите
uvicorn server.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000.

> Для локальной разработки переменные окружения не нужны. При публичном развёртывании задайте `PUBLIC_BASE_URL`,
> иначе iPhone не сможет открыть `localhost`. Полный список — в [`.env.example`](../.env.example).

## Развёртывание

> Полное пошаговое руководство по продакшену (systemd, Nginx, HTTPS, Android/iOS, R2) — в **[DEPLOY.md](DEPLOY.md)**.

В продакшене обычно запускают под systemd за reverse-прокси Nginx:

```ini
# /etc/systemd/system/webtoapp.service
[Unit]
Description=WebToApp
After=network.target

[Service]
WorkingDirectory=/path/to/web-to-app
Environment=PUBLIC_BASE_URL=https://your-domain.com
ExecStart=/path/to/web-to-app/venv/bin/uvicorn server.main:app --host 127.0.0.1 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
```

Для подписи профилей iOS (установка «без подписи») см. настройку сертификатов в [`certs/README.md`](../certs/README.md).

## Как работает оффлоад на Cloudflare R2

Сгенерированные установщики могут быть большими, и отдавать каждую загрузку с origin тратит его трафик. С настроенным R2:

1. **После каждой сборки** каждый файл из `generated/<app_id>/downloads/` зеркалируется в R2 под ключом `<app_id>/downloads/<filename>` (`server/engine/storage.py`), а полученные публичные URL записываются в `recipe.json` приложения как карта `downloads_cdn`.
2. **При загрузке** `GET /a/<id>/download/<platform>` предпочитает CDN-URL из `downloads_cdn` и отдаёт **302-редирект** на R2; при его отсутствии — откат на локальную стриминговую отдачу. Origin тратит CPU на сборках, а не трафик на каждой пересылке или сканировании QR.
3. **При очистке** объекты приложения под `<app_id>/` удаляются из R2 вместе с локальными данными.

Если любая переменная `R2_*` не задана, функция неактивна и загрузки отдаются локально — ничего не ломается. Приложения, созданные до включения R2, можно мигрировать через `python -m server.scripts.backfill_r2`. Полные шаги (бакет, API-токен, публичный доступ, собственный домен, бэкфилл) — в [DEPLOY.md §11](DEPLOY.md#11-cloudflare-r2-offload-optional).

## Замечания по безопасности

- Все секреты (R2, Cloudflare, пароли подписи) читаются из переменных окружения; в репозитории нет реальных учётных данных.
- **Приватные ключи подписи (`certs/*.keystore`, `certs/app-keys/`) и данные рантайма (`generated/`) исключены через `.gitignore` по умолчанию — никогда их не коммитьте.**
- Каждое сгенерированное Android-приложение использует собственный независимый сертификат подписи — это предотвращает массовую маркировку отпечатка сертификата и позволяет обновлять приложение на месте.
- Загружаемые авторами изображения «Об этой странице» проверяются декодированием через Pillow, ограничены потолками сырого размера / пикселей / количества, очищаются от метаданных и перекодируются в WebP — они никогда не отдаются в том виде, в каком были загружены.
- Пользовательский текст HTML-экранируется при рендере; медиа-маршруты приложений разрешают только сгенерированные сервером имена файлов.
